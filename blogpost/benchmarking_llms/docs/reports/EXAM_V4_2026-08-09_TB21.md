# exam_v4 — Terminal-Bench 2.1 on the R9700

Run window: 2026-08-07 16:01 → 2026-08-09 16:45 (Europe/Lisbon).
Machine: `hopper`. All numbers below are read back from the harbor job
directories under `artifacts/results/exam_v4_tb21/jobs/`.

## What changed from exam_v3

exam_v3 is a one-shot Go generation exam: the model is handed a prompt, emits a
single file, and a Go test binary scores it. exam_v4 replaces that with an
existing third-party agentic benchmark. The model is no longer asked to produce
a file — it drives a shell.

| | exam_v3 | exam_v4 |
|---|---|---|
| task source | written in this repo | Terminal-Bench 2.1 (89 tasks) |
| harness | `exam-driver.go` | Harbor 0.20.0, `terminus-2` agent |
| interaction | one completion | multi-turn tmux keystrokes |
| environment | none | one Docker container per task |
| scoring | `go test -race -json` | per-task verifier → `reward.txt` (0/1) |
| language | Go only | whatever the task needs |

## Setup

- **Host:** `hopper` — AMD Ryzen 5 8500G, 32 GB DDR5, Debian 13 (trixie),
  kernel 7.0.9.
- **GPU:** Radeon AI PRO R9700 (Navi 48), 32 GiB VRAM. Vulkan/RADV backend.
- **Runtime:** llama.cpp b10025 (`a3e5b96ac`), served through llama-swap v211
  on `:8090`. Single exclusive group, so exactly one model is resident at a
  time; harbor's requests trigger the swap.
- **Benchmark:** Terminal-Bench 2.1, run via the Harbor CLI 0.20.0 with the
  `terminus-2` agent. Tasks pulled with
  `harbor download terminal-bench/terminal-bench-2-1 -o ~/.cache/harbor/tasks`.
- **Shared flags** (llama-swap macro): `-ngl 999 -t 12 -fa on -sm none -mg 0
  -ctk q8_0 -ctv q8_0 --ctx-checkpoints 0 --cache-ram 2048 --no-host
  --predict 32768`.
- **Per-model:** `-c 131072 --parallel 1 --reasoning-budget 8192 --no-mmap`.
  Thinking is enabled on every arm, capped at 8192 tokens per turn.

## Task subset

The full 89-task suite extrapolated to roughly 33 h per model, so the sweep runs
on a 20-task subset.

The first subset (`calib12`, 12 tasks, hand-picked) scored 10/12 = 83% on
`qwen-35b-moe-mtp`. It had been chosen by eye and skewed toward short timeouts
and easy tiers, so it was discarded.

`strat20` replaces it: a proportional stratified random sample, seed 42,
drawn separately within each difficulty tier and sized to the real 89-task mix
— **1 easy / 12 medium / 7 hard**. It is regenerated by
`scripts/tb21-make-subset.py` rather than curated, so it can be rebuilt
byte-identically:

```
scripts/tb21-make-subset.py --name strat20 --size 20 --seed 42
```

The subset materializes as a directory of symlinks into the task cache;
harbor takes it as a single `-p` argument and derives the suite name from the
directory name.

## Invocation

```
GIT_CONFIG_GLOBAL=/dev/null OPENAI_API_KEY=llama-swap-local \
harbor run \
  -a terminus-2 \
  -m openai/<model> \
  --ak api_base=http://127.0.0.1:8090/v1 \
  -n 1 -q \
  -o artifacts/results/exam_v4_tb21/jobs \
  -p artifacts/tb21-subsets/strat20
```

One attempt per task, one trial at a time (`-n 1`) so only one model is ever
resident on the GPU.

Two environment details are load-bearing. `GIT_CONFIG_GLOBAL=/dev/null`
neutralizes a global `insteadOf` rule that rewrites https to ssh and breaks
harbor's dataset clone. `OPENAI_API_KEY` must be set to something non-empty:
llama-swap requires no auth, but litellm's `openai/` provider refuses to send a
request with no key configured.

## Scoring

Each task's verifier writes `verifier/reward.txt`, either `0` or `1`. That file
is the source of truth — not harbor's exception type, since a task can raise
`AgentTimeoutError` and still be scored by the verifier afterwards.

Tasks are weighted by tier: **easy = 1, medium = 2, hard = 3**. `strat20`'s
maximum is therefore `1×1 + 12×2 + 7×3 = 46` points.

`scripts/tb21-scoreboard.py` walks the job directories and emits both the
markdown table below and a self-contained HTML page. It merges a model's jobs
per-task, so a single re-run trial updates one task rather than replacing a
whole job.

## Notes on the runs

**Runtime is dominated by failures.** A solved task finishes in about 220 s; a
failed one burns its full `max_agent_timeout_sec`. Per-task averages therefore
track pass rate inversely, and the total for a model says more about how often
it timed out than about its decode speed.

**One trial was invalidated and re-run.** During the `gemma-26b-moe` job, an
unrelated cron job on the same host requested a different model between 08:00
and 08:05 UTC, causing four llama-swap model evictions mid-trial. The affected
task, `break-filter-js-from-html`, was re-run on its own
(`2026-08-08__13-29-41`) and the scoreboard merged the result. The other jobs
were checked against the swap log and were clean.

**Q4 vs Q6 on the same weights.** `qwen-27b-mtp` and `qwen-27b-mtp-q6` are the
same Qwen3.6-27B-MTP checkpoint at two quantization levels, same samplers, same
context, same drafter depth. They agree on 18 of 20 tasks. The two that differ
(`bn-fit-modify`, `query-optimize`) were both solved by Q4 and not by Q6. Wall
time was 7h15m vs 7h13m. Q6 costs 6.7 GiB more resident VRAM (≈24.2 vs
≈17.5 GiB of weights).

**Sample size.** Every score here is one attempt per task at n=20. Differences
of one or two tasks are inside the sampling noise of that design; the whole
5-model spread is 10 tasks wide.

**Comparison to exam_v3 is not like-for-like.** On this same host, exam_v3
scored `gemma-31b-qat` at a median 12/13 over 5 seeds — its best result there.
It places third here. The two exams were not designed to measure the same
thing, and no attempt has been made to calibrate one against the other.

## Reproducing

```
# 1. tasks
harbor download terminal-bench/terminal-bench-2-1 -o ~/.cache/harbor/tasks

# 2. subset
scripts/tb21-make-subset.py --name strat20 --size 20 --seed 42

# 3. run (per model)
scripts/tb21-run.sh <model> strat20

# 4. scoreboard
scripts/tb21-scoreboard.py --html artifacts/results/exam_v4_tb21/scoreboard.html
```

Harbor's `tb`/`harbor` CLI needs Python ≤ 3.12 (`uv tool install --python 3.12
harbor`); it crashes on 3.14. `harbor download` writes relative to the working
directory, so `-o` is required when CWD is not writable.
