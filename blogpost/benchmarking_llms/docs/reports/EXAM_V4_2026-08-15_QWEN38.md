read as a failure count. This was missed in earlier reports in this series and
should be checked when re-reading them.

## Noise floor

Per-task outcomes at `-n 1` are not stable. A direct demonstration from the
same evening: the aborted un-drafted run **passed** `break-filter-js-from-html`
(reward 1.0), and this run — same model, same task, faster decode — **timed out
on it**. The slower configuration solved a task the faster one did not.

The standing rule from `EXAM_V4_2026-08-12_MUSE_GLIMMER.md` — do not rank on a
two-point gap — applies here. The `qwen38-27b` vs `qwen-27b-mtp` tie at 14/46
and the 2-point gap to `gemma-31b-qat` are both inside it.

## What this run cost to get right

The first two attempts at this run are preserved under
`artifacts/results/exam_v4_tb21/aborted-2026-08-14-nomtp/` with their own
README. Both are invalid: the `qwen38-27b` llama-swap entry was created without
`--spec-type draft-mtp`, so the MTP head baked into the GGUF was loaded and
never used, and decode ran at 25.2 t/s instead of 42.5.

That matters more on exam_v4 than exam_v3, because the 900 s per-task agent cap
converts decode speed directly into turns-per-task. At 8192 tokens of thinking:

| config | s per think block | blocks inside 900 s |
|---|---:|---:|
| un-drafted, 25.2 t/s | ~325 | ~2.7 |
| MTP, 42.5 t/s | ~193 | ~4.7 |

`--spec-type` defaults to `none`. The AGENTS.md warning that a drafter "loads
and is never used" without it is the exact failure that occurred; it is silent,
and costs a full run.

Those aborted dirs were moved out of `jobs/` because
`scripts/tb21-scoreboard.py` scans `jobs/*/` and merges every directory
belonging to a model — leaving them in reported `qwen38-27b` runtime as
"31h00m (running)". Scores were unaffected; only the runtime column was wrong.

## Caveats

- One attempt per task, `-n 1`. Nothing here supports ranking on ≤2 points.
- Agent timeout left at the 900 s default, as in all six prior arms. Raising it
  would improve the measurement and break comparability with every existing
  row.
- `terminus-2` still does not manage its own context (runbook §3.2b); served
  at `-c 131072` to compensate.
- Runtime is wall-clock for the whole job including environment setup and
  verification, not model time.
